# GitHub 交付与外网演示部署

## 当前能力与部署边界

本项目是 **Windows 本机演示启动器**。GitHub 用于保存代码、审查变更和运行自动测试；GitHub Pages 只能托管静态文件，无法运行 Express、Playwright、Windows 演示程序或密集架隧道。

当前版本没有实现公网登录、远程浏览器画面传输或多人桌面调度。仅改为监听 `0.0.0.0`、映射 3001 端口或使用 HTTP 反向代理，仍无法让同事看到后端打开的浏览器。不要把导航台接口直接暴露到公网。

现有 8 个入口包括 **7 个网页系统和 1 个客户端安装入口**。安装包进程启动成功不代表客户端已经安装或可以使用。源码测试通过、网页返回 HTTP 200，也不能替代真实外网演示验收。

## 推荐部署方式：Windows 演示主机与网页远程桌面

同事的浏览器 → HTTPS 与身份验证 → 远程桌面网关 → Windows 演示桌面 → 本机导航台、Chromium、演示程序和艾搜客户端。

远程桌面传输整台演示主机的画面与操作，因此可以保留原生 Windows 程序和 Playwright 自动登录。密集架隧道和所有目标系统请求从 Windows 主机发出。同事在远程桌面里的浏览器打开 `http://127.0.0.1:3001`；**同事自己电脑的这个地址不是公网入口**。

可使用已有云桌面产品或 Apache Guacamole 等 HTML5 远程桌面网关。本仓库不包含已部署的网关，也未创建公网网址。网关本身须单独配置和验收，参考 [Apache Guacamole 官方部署文档](https://guacamole.apache.org/doc/gug/)。

部署前需要确定：

1. Windows 演示主机的位置、操作系统、管理员维护方式，以及能否安装授权的花都程序与隧道。
2. 网页远程桌面网关、HTTPS 域名与同事登录方式；建议每人独立账号、MFA 和会话过期策略。
3. 同时演示人数。一个共享桌面只适合轮流操作；独立并发演示应分配独立 VM 或已获得适当授权的 Windows/RDS 会话。普通 Windows 桌面版不能直接承诺多人同时使用。
4. 目标演示账号是否允许同时登录；不同 Chromium context 只隔离浏览器 Cookie，不能改变目标系统的账号并发规则。
5. 艾搜是运行在远程演示桌面，还是必须安装到每位同事本机。

公网只开放有认证的 HTTPS 网关。RDP 等桌面协议仅允许来自网关或专用网络的连接；导航台继续保持回环地址绑定。网关服务器和演示主机可以分开部署，网关所在机器必须能访问 Windows 主机的桌面协议端口。

## 准备可提交到 GitHub 的源码

在当前项目目录运行：

```sh
npm run export:source
```

命令在 `dist/archive-demo-nav-source-*` 新建交付目录，使用明确的文件清单，仅复制源代码、无凭据配置模板、依赖锁文件、测试和工作流。不会复制 `config/systems.js`、安装包、隧道配置、日志或 `node_modules`。新增需要交付的代码文件时，同步更新 `scripts/export-source.js` 的清单。

将导出目录的**内容**作为 GitHub 仓库根目录，包含 `.github` 和 `.gitignore`。不要直接上传正在运行的整个工作目录。若配置文件以前进入过 Git 历史，忽略规则无法清除历史；应先撤换其中的凭据并处理历史记录。

GitHub Actions 在 Ubuntu 和 Windows 上运行 `npm ci`、安装 Chromium、执行 `npm test`。测试使用本地模拟网页和虚构账号，不需要真实系统配置或 GitHub Secrets。工作流只做代码验证，不部署外网演示环境，也不自动检查真实系统账号。

## 自动发布公开导航网址

仓库包含 `.github/workflows/pages.yml`。在 GitHub 仓库的 **Settings → Pages → Build and deployment** 将 Source 设为 **GitHub Actions**，并确保该仓库允许 Pages 发布。工作流目前监听 `main` 分支；如果仓库使用其他默认分支，先修改工作流里的分支名。每次把代码推送到该分支会构建静态入口并部署 Pages；成功运行的工作流页面会显示 GitHub 提供的网址，常见格式为 `https://<用户名>.github.io/<仓库名>/`。

在 **Settings → Secrets and variables → Actions → Variables** 创建变量 `DEMO_DESKTOP_URL`，值填写已部署、受身份验证保护的 HTTPS 远程桌面网址（例如 Guacamole 的客户端入口）。随后重新运行 Pages 工作流。该网址会公开出现在已发布页面配置中，**只能放网址，不能放用户名、密码、访问令牌或其他密钥**。认证应由远程桌面网关独立提供，例如要求每位同事使用自己的账号登录，并按组织要求启用 MFA。

如果尚未设置 `DEMO_DESKTOP_URL`，Pages 工作流仍会发布导航页面并输出网址。8 张系统卡片会保留“系统演示”按钮；点击后会明确提示演示主机尚未接入，页面不会伪称已经打开系统。卡片使用 `public/hosted.js` 中不含密码的展示清单，因此修改本机 `config/systems.js` 不会自动改变 Pages 卡片；公开名称、网址、账号和配置状态需要同步维护。配置远程桌面后，8 张卡片共用一个 Windows 桌面。同事进入桌面后仍需打开桌面内的原导航台，再选择对应系统。因此页面提供外网入口，实际浏览器、登录和原生程序仍运行在 Windows 主机。一次只有一位同事操作同一个共享桌面；多人同时演示应提供彼此隔离并按授权配置的桌面会话或 VM。

发布页面前需要先部署可从公网访问的认证网关及 Windows 演示主机。仅填写变量不会创建远程桌面，也不能把本机导航台自动变成公网服务。网关、Windows 主机、证书、身份认证和隧道均须在机构授权的环境独立部署。

## 在 Windows 演示主机初始化

使用 Node.js 24 LTS。将 GitHub 项目克隆到这台主机后，在项目目录运行：

```powershell
npm ci
npx playwright install chromium
if (-not (Test-Path -LiteralPath 'config/systems.js')) {
  Copy-Item -LiteralPath 'config/systems.example.js' -Destination 'config/systems.js'
}
```

由管理员在主机上填写真实账号和密码，按实际位置配置附件路径。真实配置独立交付，不上传 GitHub；限制该文件和备份的读取权限。模板保留 7 个网页系统的网址，账号密码为空；艾搜需要补齐本机安装包配置后启用。

密集架需要迁移**完整演示程序目录及其依赖**，不能只复制单个 EXE。按照软件提供方要求在新主机安装、授权和配置隧道；不要直接把原电脑的隧道密钥上传仓库。验证新主机能到达 `192.168.3.251`，再设置 `externalDemo.executable`、`cwd` 和服务名。窗口标题和按钮配置也应与实际版本一致。

在同一个交互式 Windows 会话中运行导航台和花都演示程序。后台服务的 Session 0 不能提供可见、可操作的桌面；锁屏、权限级别不一致及多人争用鼠标也会影响按钮自动化。若需要管理员权限，应由主机管理员完成程序与隧道准备，并安排受控的演示会话。

艾搜安装包约 675 MB，应由受控文件分发渠道、符合容量限制的 Release 附件或对象存储交付。安装包不进入 Git 源码。管理员需在演示主机上完成安装及客户端启动验证；当前按钮打开的是后端主机的安装包，不会把它下载到同事电脑。若要求同事本机安装，还需单独配置下载入口；网页登录自动化不能替其安装软件。

## 检查与运行

```powershell
npm test
npm run check
npm run check:network
$env:PORT = '3001'
npm start
```

- `check`：检查本机配置、所需文件和浏览器安装情况；不启动安装包或提交真实账号。通过仅表示静态前提满足，桌面、登录和客户端仍需实际验证。
- `check:network`：增加从当前主机发出的 HTTP 连通性检查，不提交登录，不验证业务权限或页面资源加载完整性。
- `check:public`：当前版本会明确报告直接公网部署不满足并返回非零退出码。这是部署边界检查，不能通过修改此退出码把本机应用变成远程演示平台。

在 Windows 演示桌面的浏览器打开 `http://127.0.0.1:3001`，确认显示 8 个系统入口。保持该会话中的 Node 进程运行；关闭进程会影响自动化浏览器。断开远程连接后能否保留可操作桌面，取决于所选远程桌面产品，必须实测；重新启动主机后也要验证恢复流程。

## 外网验收

完成网关部署后，由至少两名同事使用不同外部网络访问实际 HTTPS 入口，并根据预计并发人数测试。未完成以下步骤前，不能标记“全部系统可公网演示”。

1. 同事通过身份验证进入分配的桌面；退出登录或会话过期后无法继续操作。不同独立会话看不到彼此的桌面和登录状态。
2. 在远程桌面内打开导航台，点击智能文件柜、AI辅助数字化扫描加工、档案数字化管理、综合档案管理、干部人事档案管理、综合单机版六个入口。逐项确认自动登录结果，打开至少一个只读业务页面，并验证鼠标、键盘、页面切换和退出。
3. 点击密集架入口，确认隧道可连接、一体化平台 3.2 可访问、自动登录完成，并打开一个只读演示页面。确认现有隧道不会影响其他演示会话。
4. 艾搜完成安装、启动和必要的登录配置后，验证客户端实际可使用；如要求本机安装，另测外网下载完整性及本机运行。安装包存在或启动不算验收通过。
5. 检测到验证码或二次验证时，能在远程桌面人工接管；网络故障时显示中文原因，保留可用窗口。
6. 验证并发登录、断开重连、会话回收、主机重启后的恢复与目标账号的并发限制。
7. 从同事电脑直接请求导航台端口应不可达；公开代码与接口响应不含密码。只有网关认证后才可以使用演示桌面。

目标站点、演示账号、隧道和软件授权均属于外部依赖；需要由相应维护者保持可用。本仓库的检查工具不会替这些外部服务作可用性保证。
